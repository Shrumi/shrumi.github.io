AI-помощник по установке Windows

Ассистент, который отвечает на вопросы по установке и настройке Windows на основе собственной базы знаний: ошибки установки, BIOS/UEFI, драйверы, BSOD, диски, активация. Ниже — как устроен пайплайн и что уже работает.

Как это работает

Что это

Классический RAG-контур: документы → чанки → эмбеддинги → гибридный поиск → реранкер → ответ со ссылкой на источник. Задача — не «поговорить про Windows», а находить конкретное решение по коду ошибки или симптому и показывать, откуда оно взято.

Сейчас это MVP: база из 24 заметок, локальный поиск, демо-виджет в браузере. Генерация ответа языковой моделью — следующий этап, в демо ответ собирается из найденных фрагментов.

Составные части

База знаний

24 заметки в 8 разделах: установка, первичная настройка, сеть, обслуживание, диагностика, диски, автоматизация, софт. Markdown с командами и кодами ошибок.

Чанкинг

Разбиение по заголовкам ## и ###, а не по символам. Заголовок склеивается в контекст чанка: «Windows > Диагностика > BSOD».

Эмбеддинги

Модель multilingual-e5-base, 768 измерений, косинусное расстояние. Векторы хранятся в Qdrant.

Гибридный поиск

Dense-поиск по смыслу + BM25 по точным токенам. Слияние через RRF. Коды ошибок вроде 0x80070002 находит именно BM25.

Реранкер

jina-reranker-v2-base-multilingual пересортировывает топ-20 кандидатов и оставляет 5. Отсекает «похожее, но не то».

Виджет

Всплывающий чат на этой странице. В демо — BM25-поиск по базе прямо в браузере, без сервера.

Логическая цепочка пайплайна

1
Сбор и структурирование Материалы раскладываются по жизненному циклу системы: установка → настройка → сеть → обслуживание → диагностика → диски → автоматизация → софт.
↓
2
Извлечение и чанкинг Markdown режется по заголовкам, в каждый чанк добавляется путь раздела и метаданные: файл, дата, тип.
↓
3
Индексация Чанки превращаются в векторы и складываются в Qdrant. Параллельно строится BM25-индекс по сырому тексту.
↓
4
Поиск Запрос идёт двумя путями: векторный (смысл) и лексический (точные коды, команды, имена файлов). Результаты сливаются через RRF.
↓
5
Реранкинг Кросс-энкодер оценивает пары «запрос — фрагмент» и переставляет топ. Это дороже, но точнее векторного сходства.
↓
6
Ответ Пользователь получает решение и ссылку на источник. Если релевантных фрагментов нет — честное «в базе нет», без выдумывания.

Ограничения демо

  • Виджет ищет по предзагруженному JSON, а не обращается к Qdrant — GitHub Pages не держит бэкенд.
  • Ответ собирается из найденного фрагмента, без переформулировки моделью.
  • База небольшая: 24 заметки, 185 чанков. На реальном корпусе нужен мониторинг качества.

Стек

  • Python 3.12, sentence-transformers, rank_bm25
  • Qdrant 1.20 (векторная БД) + собственный прокси для Web UI
  • multilingual-e5-base (эмбеддинги), jina-reranker-v2-base-multilingual (реранкинг)
  • Статический сайт на GitHub Pages
